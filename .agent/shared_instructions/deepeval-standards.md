# DeepEval & Confident AI — LLM Testing Standards

This document defines the project's standards for LLM evaluation using DeepEval and Confident AI.

---

## 1. Environment Configuration

Evaluation requires authentication for both the LLM provider (Gemini/Vertex AI) and the evaluation dashboard (Confident AI).

- **`CONFIDENT_API_KEY`**: Required for uploading test results. Use environment-specific keys (dev, qa, prod).
- **`GCLOUD_PROJECT`**: Required for Vertex AI (Gemini) judge model.
- **`APP_ENV`**: Used to switch between dev, qa, and prod environments in Confident AI.

---

## 2. Test Case Structure (LLMTestCase)

All evaluations must use the `LLMTestCase` class. Required fields depend on the metric being used.

| Field | Description | Required By |
|---|---|---|
| `input` | The user query or prompt. | All metrics. |
| `actual_output` | The response generated by the LLM. | All metrics. |
| `expected_output` | The ground-truth answer. | ContextualPrecision, ContextualRecall, Summarization, GEval (when referenced). |
| `retrieval_context` | Chunks retrieved from the RAG pipeline. | Faithfulness, ContextualPrecision, ContextualRecall, ContextualRelevancy. |
| `context` | Ground-truth facts for the LLM. | Hallucination. |

---

## 3. Core Metrics & Thresholds

| Metric | Threshold (Typical) | Purpose |
|---|---|---|
| `AnswerRelevancyMetric` | 0.7 | Does the response actually answer the input query? |
| `FaithfulnessMetric` | 0.8 | Does the output factually align with the retrieved context? |
| `HallucinationMetric` | 0.2 (Max) | Detects fabrications or contradictions against ground truth. |
| `GEval` | 0.7 | Evaluates subjective criteria like tone, style, and correctness. |

---

## 4. GEval Criteria Best Practices

- **Atomic Criteria**: One criterion per `GEval` instance (e.g., separate "Tone" from "Correctness").
- **Explicit References**: Always refer to the input, actual output, or expected output specifically.
- **Specific instructions**: "Determine whether the actual output is factually correct based on the expected output."

---

## 5. Judge Model Standards

- **Model**: Always use **Gemini 2.0 Flash** (via `GeminiVertexAI`) as the judge model for cost efficiency and speed.
- **Configuration**: Use the `GeminiVertexAI` class from `deepeval.models`.

---

## 6. Execution Patterns

- **`deepeval test run`**: Always use this command instead of plain `pytest` to ensure results are uploaded to Confident AI.
- **Parallel Execution**: Use the `-n` flag (e.g., `-n 4`) to run test cases concurrently and save costs/time.
- **Caching**: Use the `-c` flag for faster iterative testing by skipping unchanged test cases.
- **ID Management**: Always provide a unique `-id` for each run (e.g., `dev-$(date +%Y%m%d)`) to easily locate runs in the dashboard.

---

## 7. Async Support (LangGraph)

- **Native Async**: Use `async def test_...` with the `pytest-asyncio` plugin (configured with `asyncio_mode = "auto"`) to test LangGraph nodes.
- **Fixtures**: Use `scope="session"` for graph compilation and judge model initialization to keep tests fast.
