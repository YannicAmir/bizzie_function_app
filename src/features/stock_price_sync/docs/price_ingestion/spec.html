Stock Price Sync — Price Ingestion
Three-phase per-ticker pipeline: pre-open EOD seed · intraday 1-min snapshot · post-close EOD finalize · idempotent Firestore overwrite

On weekdays this pipeline reads the global watchlist and keeps one compact snapshot per ticker in stock_prices/{ticker} fresh, in three ET phases: a pre-open EOD seed (9:15–9:29) that establishes each ticker's previousClose from the prior session's official closing-auction price; the intraday loop (9:30–4:05pm) that fetches each ticker's current-session 1-minute chart, derives a compact snapshot (latest price, change vs previous close, sparkline series), and overwrites the document; and a post-close EOD finalize (4:20pm+) that replaces the day's price with the official close once the ~15-min-delayed EOD record publishes. One API call per ticker per phase — neither the 1-min chart nor the EOD endpoint supports multi-symbol queries, and no bulk/batch endpoint is on the current FMP plan.

FunctionTriggerSchedule
stockPriceSyncCloud Scheduler* 9-16 * * 1-5 (America/New_York), gated in code into pre-open seed / intraday / post-close finalize phases
The keystone property: each run writes a complete, self-contained snapshot of the current session. Nothing is appended, accumulated, or cursored. Any failure — one ticker, one run, a whole outage — is fully repaired by the next successful run, at most 60 seconds later. Retries, queues, and dead-letter handling are structurally unnecessary: the schedule is the retry.

Orchestration — Use Case Steps

Step 1 resolves the phase from the current ET time and dispatches. The per-ticker body (Step 4) runs concurrently under a fetchConcurrency limit with per-ticker error isolation. execute() is a thin orchestrator — it owns only the step sequence and delegates each step to a named method (resolvePhase, loadWatchlist, selectCohort, processCohort, logRunSummary) or sibling module (phase.ts, cohort.ts, previous_close.ts, snapshot.ts, core concurrency.ts).

Phase gate (Step 1)

ET windowPhaseAction
< 9:15, 16:06–16:19, or > 16:59IDLEdebug log and return (cron fires but there is nothing to do)
9:15–9:29pre-open EOD seedwarm previousClose for the cohort from the EOD endpoint; no Firestore writes
9:30–16:05intradaythe per-ticker 1-min snapshot loop (unchanged core behavior)

All phases share load watched tickers (Step 2) and cohort selection (Step 3), run the phase body per ticker under the concurrency limit (Step 4), then emit a summary log (Step 5). Step 2: core FirebaseWatchlistService.getAllWatchedTickers() → Map<ticker, companyName>, cached at module scope for watchlistCacheSeconds (default 300s). Step 3: maxCallsPerRun = 0 (default) → all tickers; otherwise numCohorts = ceil(N / maxCallsPerRun), sorted tickers, keep index % numCohorts === minuteOfDay % numCohorts.

Module-scope caches

  • previousCloseCache: Map<ticker, {sessionDate, previousClose}> — owned by previous_close.ts (managed via PreviousCloseResolver.isFresh/cache); one EOD seed per ticker per day (cached even when null).
  • latestBarAtCache: Map<ticker, latestBarAt> — in usecase.ts; intraday unchanged-skip key; set only after a successful write.
  • finalizedCache: Map<ticker, sessionDate> — in usecase.ts; marks a ticker finalized today; makes the finalize phase self-disabling and idempotent.

Phase body — pre-open EOD seed (9:15–9:29)

Per ticker (processSeed): if PreviousCloseResolver.isFresh(ticker, today), skip. Otherwise PreviousCloseResolver.resolve(ticker, cfg, today) — EOD narrow fetch (from = today − eodLookbackCalendarDays, default 4; to = today), take close of the newest record with date < today; on no prior record, one widened retry (today − eodFallbackCalendarDays, default 10) — then cache(...) under today's sessionDate (including null). No snapshot, no write — there are no today bars yet; the phase only front-loads the EOD calls off the intraday hot path.

Phase body — intraday (9:30–16:05)

  1. Resolve previousClose (cache-first) & fetch today's bars — PreviousCloseResolver.resolveCachedPreviousClose(ticker, cfg, today): cache hit → use it; miss (cold instance) → resolve and cache. A failed EOD fetch here warns and returns null (not cached — retries next run); price/series still write with change = null. Then FmpChartService.fetchIntradayBars(ticker, {from: today, to: today}); failure after retries → logged, counted, continue (stale ≤ 60s).
  2. Build snapshot — buildIntradaySnapshot(...) (pure, snapshot.ts): keep only bars whose date prefix equals today's ET date; sort ascending; sessionDate = today, price/latestBarAt = newest raw 1-min bar; change/changePercent from previousClose (null when unavailable); series = bars downsampled into seriesBucketMinutes buckets (in-progress bucket included so the tip equals price); closeFinalized = false. No today bars → skip, doc untouched.
  3. Skip if unchanged — latestBarAtCache equal → no write.
  4. Upsert — full-overwrite set() + updatedAt server timestamp; on success set latestBarAtCache. Failure → logged, counted.

Phase body — post-close finalize (16:20–16:59)

Gated by resolveFinalizeClose(ticker, cfg, today), which returns a discriminated FinalizeGate ({proceed: true, previousClose, officialClose} or {proceed: false, outcome}):

  1. Fetch today's official close — PreviousCloseResolver.resolve(...) (widen-on-miss); one response yields both the record for date === today (official close) and the newest record before today (previousClose, for cold instances). EOD failure → {proceed:false, 'failed'}. Already finalized (finalizedCache holds today) → {proceed:false, 'skipped'}. No record for today yet (the ~15-min-delayed EOD not published) → {proceed:false, 'skipped'}; a later run retries — guarded on the EOD record's date, never on the clock. On proceed, the resolver caches previousClose under today.
  2. Fetch today's frozen 1-min series — fetchIntradayBars(ticker, {from: today, to: today}) (session over, series stable). No today bars → skipped.
  3. Build finalized snapshot — buildFinalizedSnapshot({..., previousClose, bucketMinutes}, officialClose) (pure, snapshot.ts): price = official close; append {t: MARKET_CLOSE_LABEL "16:00", c: officialClose} so the tip equals price; change/changePercent against previousClose; latestBarAt unchanged (still 15:59); closeFinalized = true.
  4. Upsert (bypasses the unchanged-skip) — the finalize write must not consult latestBarAtCache (latestBarAt hasn't changed since 15:59, so the intraday skip would wrongly suppress the correction); writes unconditionally (full-overwrite set()), then records finalizedCache.set(ticker, today). Idempotent. Counted written.

Step 5 — Summary log: phase + written/skipped/failed of total + duration ms. Intraday duration > 45s logs at WARN — the watchlist has outgrown the concurrency/timeout budget.

Retention note: "current session only" applies to what a write contains, not when documents vanish — overnight/weekends/holidays there is nothing new to write, so each document retains the last completed session with closeFinalized = true (the overnight-displayed price is the official close). sessionDate identifies the session.

Domain Types

interface IntradayBar {
  date: string;      // "YYYY-MM-DD HH:mm:ss" — US/Eastern, lexicographically sortable
  open: number;
  low: number;
  high: number;
  close: number;
  volume: number;
}

interface DailyClose {
  date: string;      // "YYYY-MM-DD" (ET) — one record per trading day (closed days absent)
  close: number;     // official (unadjusted) EOD close; the FMP EOD DTO's `price`
}

interface PricePoint {
  t: string;         // "HH:mm" ET of the bucket's newest bar — sessionDate supplies the date
  c: number;         // that bar's close
}

interface PriceSnapshot {
  ticker: string;                 // uppercase
  companyName: string;
  price: number;                  // intraday: newest 1-min bar close; after finalize: official EOD close
  previousClose: number | null;   // prior session's official EOD close (daily EOD fetch)
  change: number | null;          // price − previousClose
  changePercent: number | null;   // change / previousClose × 100
  sessionDate: string;            // "YYYY-MM-DD" (ET) — always the current session at write time
  series: PricePoint[];           // current session, downsampled to seriesBucketMinutes buckets (+ 16:00 close point on finalize)
  latestBarAt: string;            // newest 1-min bar date — intraday unchanged-skip key
  closeFinalized: boolean;        // true once the official EOD close has replaced the last-trade price
}

date strings are compared lexicographically everywhere; nothing is parsed to Date except the phase gate and window-date computation, done in America/New_York like stock_news_notifier. change/changePercent measure the day's move against the prior session's official EOD close (the exact auction close) from the daily EOD fetch; both are null when previousClose is unavailable (null or 0). During the session price is the newest 1-min bar with closeFinalized = false; after finalize it is the official close (with an appended 16:00 series point) and closeFinalized = true.

Firestore Schemas

watchlist/{ticker} — read

Written by watchlist_aggregator, read via the core FirebaseWatchlistService: ticker (doc ID), companyName, lastAddedAt.

stock_prices/{ticker} — written

StoredStockPrice — PriceSnapshot plus updatedAt. Full-overwrite set() (never merge), intraday and on finalize: the document is a pure projection of the latest fetch. series only ever contains the current session (plus the 16:00 close point after finalize), downsampled server-side to seriesBucketMinutes buckets — ~79 points ≈ 2 KB at the default 5 min. The added closeFinalized boolean tells the client the close is authoritative. One doc per ticker, bounded by watchlist size — no TTL, no cleanup.

Front-end read pattern. One-time fetches on home-tab view or pull-to-refresh — no continuous listeners (a deliberate cost decision: read volume scales with user activity, not with market-hours write volume). Direct document reads, no queries, no composite indexes:

db.collection('stock_prices').doc(ticker).get()   // one get per watched ticker per refresh
Outside market hours the document holds the last completed session with closeFinalized = true, so the front end renders the official close for the latest available session — sessionDate identifies it.

Single fetch mode — today-only

The use case always calls this with from = to = today (ET). This keeps the feature at ~18% of the plan's 500 GB / rolling-30-day bandwidth cap (a multi-day window every minute would total ~570 GB/30d):

ModeWindowPayload
Today-only (every call)from = to = today0→43 KB, growing through the day
The post-close finalize phase re-uses this same today-only fetch to read the now-frozen session series before overwriting price with the official close. The former 1-min previous-close seed (multi-day lookback, weekday-aware narrow window, widen-on-miss) is removed — previousClose now comes from the EOD endpoint, which is both more accurate and simpler.

Thin endpoint wrapper. FmpChartService holds no HTTP/retry logic — it constructs a shared FmpClient and declares one FmpEndpoint<IntradayBar> (path, label: 'intraday', error codes, parseRow: parseFmpBar). fetchIntradayBars(ticker, window) delegates to FmpClient.fetchWindowedRows. parseFmpBar drops rows missing a string date or finite close (open/low/high/volume default to close/0); the client logs the drop count once per ticker. Returns unsorted validated bars — sorting/session-filtering/derivation belong to the use case. Empty array is valid (holidays, new listings). Retry/timeout/transient policy is inherited from the client.

Service — fmp_eod_service

Fetches the official end-of-day close — the authoritative source for both previousClose and the finalized close of the current session, the values the 1-min endpoint cannot provide. A separate service from the chart service: different endpoint, DTO, and validation boundary (daily records, not intraday bars).

Service — fmp_client (shared)

Both FMP services delegate here. Every FMP call in the feature is a single windowed, single-symbol, bounded GET, so the fetch/retry/timeout/validation machinery is factored once and each service becomes a typed endpoint descriptor.

interface FmpEndpoint<T> {
  path: string;                 // e.g. '/historical-chart/1min'
  label: string;                // error/log label ('intraday' | 'EOD')
  fetchFailedCode: string;      // AppError code for a non-ok response
  invalidResponseCode: string;  // AppError code for a non-array body
  parseRow: (item: unknown) => T | null;   // boundary validation; null = drop
}

fetchWindowedRows<T>(endpoint, ticker, window): builds {baseUrl}{path}?symbol=…&from=…&to=…&apikey=…, wraps the request in retry() with a 10s AbortSignal.timeout per attempt; non-ok → AppError(fetchFailedCode, status); non-array body → AppError(invalidResponseCode, 422); maps rows via parseRow, dropping nulls with one info log per ticker.

Transient policy. Retry maxAttempts 3, 1s → 2s → throw. isTransientError retries only AppError.status ∈ {429, 500, 502, 503, 504}, network errors, and timeouts; a 422 non-array body and a malformed-JSON SyntaxError (both FMP contract changes) are not retried — they fail fast and surface. This is the single place the whole feature's FMP resilience is defined.

Service — firestore_service

upsertPrice(snapshot) — guards a non-empty snapshot.ticker (throws before any write), builds a typed StockPriceWrite (Omit<StoredStockPrice,'updatedAt'> & { updatedAt: FieldValue }), then full-overwrite set() on stock_prices/{ticker} with updatedAt: serverTimestamp(). Never merge (stale fields would survive shape changes and break the idempotency argument). Logs and rethrows on failure — isolation and counting live in the use case's writeSnapshot; no in-process retry, the next run's rewrite is the retry. No transactions, no state documents, no delete path (watchlist is append-only).

Remote Config — stock_prices_config

Created with the JSON data type (like stock_news_config), parsed into AppConfig.stock_prices:

stock_prices: {
  fetchConcurrency: number;         // default 8    — parallel FMP calls
  maxCallsPerRun: number;           // default 0    — 0 = all tickers/run; > 0 = round-robin cohorts
  watchlistCacheSeconds: number;    // default 300  — per-instance watchlist cache TTL

All knobs runtime-adjustable without a deploy. Migration note: the earlier seedFallbackCalendarDays knob (widen-on-miss for the 1-min previous-close seed) is removed — the 1-min seed is gone; previousClose now comes from the EOD endpoint, whose window is tuned by eodLookbackCalendarDays / eodFallbackCalendarDays.

Design Decisions — Why Not Pub/Sub

The original plan (scheduler → per-ticker Pub/Sub messages → subscriber makes the API calls, "in case of failures") correctly identified the forced per-ticker fan-out. The Pub/Sub layer is rejected:

ConcernAnalysis
Retries are anti-valueA redelivered message executes minutes later, delivering data the next scheduled run has already superseded. Every retry is wasted work racing a fresher full refresh.
Rate limiting gets worseFan-out across auto-scaled subscribers makes aggregate FMP concurrency unbounded → thundering-herd 429s. One function + fetchConcurrency + maxCallsPerRun is precise and Remote-Config-tunable.
Cost & noise~720k invocations/day (publishes + subscriber runs + topic/DLQ/monitoring) vs ~481/day.
Duplicate/ordering hazardsAt-least-once delivery can overwrite fresher snapshots with staler ones unless writes carry version guards — complexity defending against a self-inflicted problem.
Contrast with weekly_recap, where Pub/Sub is justified: minutes of LLM work per message on a weekly cadence — a lost company is a lost week. Here the unit of work is a ~300ms GET refreshed ~390×/day; losing one costs 60 seconds of staleness. Revisit if per-ticker work ever becomes expensive and loss-intolerant.
  • Official close from the EOD endpoint, not the 1-min last bar — the 1-min endpoint's final bar (15:59) is a last-trade price and misses the 16:00 closing auction; the two routinely differ (confirmed end-to-end). price at/after close and previousClose are sourced from historical-price-eod/light's official close. The EOD endpoint is ~15-min delayed, so finalize runs from 4:20pm and is guarded on EOD.date === today, not the clock — it no-ops and retries until the record publishes, then self-disables via an in-memory finalizedCache. No bulk/batch EOD on the plan (confirmed), so EOD stays per-ticker — ≤ 2 calls/ticker/day, a rounding error.
  • Finalize must bypass the unchanged-skip — the finalize write changes price without a new bar (latestBarAt is still 15:59), so routing it through the latestBarAt skip would silently drop the correction. Finalize writes unconditionally (still a full-overwrite set(), still idempotent) and tracks completion in a separate finalizedCache. This is the subtlest hazard in the design and the reason finalize is a distinct phase.
  • One function, three phases, not two functions — the finalize pass could be a separate scheduled function, but keeping it in the same use case shares the per-ticker concurrency/error-isolation harness, the services, one log stream, and one kill switch; the phases are mutually exclusive in time, so there is no contention.
  • Series tip stays equal to price after finalize — rather than relax the "tip == price" invariant, finalize appends one synthetic { t: "16:00", c: officialClose } point; cosmetic on a sparkline but keeps the doc self-consistent so the front end never special-cases the finalized doc.
  • Full-session snapshot, not quote-tick accumulation — quote endpoints unavailable (confirmed 2026-07-16); accumulation would also need gap/seed/backfill logic. If batch-quote ever becomes available: batch-fetch prices per minute, drop this pipeline to a lower cadence for series — the doc shape already supports the split.
  • Intraday today-only fetch window — driven by the 500 GB/30d bandwidth cap: every 1-min call fetches from = to = today (~92 GB/30d ≈ 18%); a multi-day window every minute would be ~570 GB and exceed the cap. previousClose no longer rides on this endpoint — it comes from the EOD endpoint.
  • Prior-session close from EOD, narrow window + widen-on-miss, no holiday calendar (supersedes the 1-min seed) — previousClose = the newest EOD record with date < today, one windowed fetch/ticker/day, cached in memory. Narrow window (today − eodLookbackCalendarDays, default 4) + widen-on-miss (today − eodFallbackCalendarDays, default 10). Closed days are absent, so "newest record before today" is always the correct prior session. Rejected a holiday package (wrong for NYSE, can't predict ad-hoc closures). Retired the former weekday-aware 1-min seed: it worked but its close was the skewed 15:59 last-trade price and was more code — EOD is more accurate and simpler, so the 1-min seed and its seedFallbackCalendarDays knob are deleted.
  • Current session only in Firestore; documents never blanked — outside market hours each doc retains the last completed session with closeFinalized = true, so the overnight-displayed price is the official close, not the 15:59 last trade; sessionDate identifies the session.
  • No lease, no state doc — unlike stock_news_notifier, there is no cursor to corrupt; maxInstances: 1 suffices and last-write-wins is correct. The only per-instance state is three in-memory caches, rebuilt harmlessly on cold start.
  • Embedded series array, not a points subcollection — one read, atomic replace; a subcollection costs one read per point per chart render.
  • Series downsampled server-side to 5-min buckets — a mini sparkline has fewer horizontal pixels than a session has 1-min bars, so raw storage ships ~5× the bytes for zero visual gain; each bucket contributes its newest bar, in-progress bucket included so the series tip equals price.
  • Cron + in-code phase gate — a single cron expression cannot express 9:15/9:30/4:05/4:20 boundaries; the gate routes each minute into pre-open seed / intraday / finalize / idle, and an idle exit costs milliseconds and zero FMP calls.
Consistency guarantees: Documents — always internally consistent (atomic full overwrite). Freshness — ≤ 60s behind the FMP feed in-session. Recovery — unconditional: any failure heals on the next successful run, no operator action.

Resolved Decisions

DecisionResolution
Official close vs 1-min last tradeThe 1-min final bar (15:59) misses the 16:00 closing auction — confirmed the two differ. price (at/after close) and previousClose come from the EOD light endpoint's official close, not 1-min bars.
Change vs previous closeMeasured against the prior session's official EOD close (the exact auction close, not ± a cent), sourced by one EOD windowed fetch/ticker/day; null when unavailable.

Today's close finalizationA post-close EOD finalize (4:20pm+) overwrites price, appends a 16:00 series point, sets closeFinalized = true. Guarded on EOD.date === today; self-disabling via an in-memory marker.
1-min seed removedThe former weekday-aware 1-min previous-close seed (narrow + widen-on-miss) is deleted — EOD supersedes it, more accurately and with less code.
FMP per-minute quotaEnterprise, 1,500 calls/min. Intraday ~33%; EOD adds two short ~500-call bursts/day — no cohorting needed at current scale.
FMP bandwidth cap500 GB / rolling 30 days — drove the intraday today-only window (~18%). EOD payloads negligible. Monitor the dashboard the first week in prod.
Extended hoursNot on the plan — regular session only.
Storage scopeCurrent-session series only (plus the synthetic 16:00 close point after finalize); the only prior-session value stored is the previousClose scalar (and derived change/changePercent).
Series downsamplingseries stores one point per seriesBucketMinutes bucket (default 5 → ~79 points, ~2 KB); finalize appends a 16:00 official-close point; price/latestBarAt stay minute-fresh intraday from the newest raw bar.
Off-hours retentionDocuments never blanked — the front end pulls the latest available (finalized) session; the overnight price is the official close.
Price stalenessIntraday ≤ ~60s (poll cadence; × numCohorts if throttling is enabled); the official close lands by ~4:20pm (one finalize pass). Tick-level real-time would be a websocket/streaming architecture — out of scope.
