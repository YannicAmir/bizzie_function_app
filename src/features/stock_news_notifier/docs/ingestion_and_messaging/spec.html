Stock News Notifier — Ingestion & Messaging
Minute-cadence FMP news poller · watchlist filter · idempotent Firestore storage (3-day TTL) · coalesced FCM topic notifications

Every minute this pipeline fetches the newest stock news from FMP, keeps only articles whose ticker is on the global watchlist, stores them idempotently in Firestore (3-day TTL), and sends one coalesced FCM topic notification per ticker. An ingestion cursor (high-water mark on publishedDate) plus an overlap window and create-only writes make the pipeline exactly-once for storage and at-least-once-with-dedup for notifications.

FunctionTriggerSchedule
stockNewsNotifierCloud Scheduler* 4-23 * * * — every minute, 4:00am–11:59pm EST (America/New_York)
Consistency guarantees: Storage — exactly-once effect (at-least-once fetch + idempotent create()). Notifications — at-most-once per ticker per cooldown window (transactional claim-before-send). Coverage — no gaps (cursor only advances over fetched data; failed runs re-cover; deep gaps route through ranged backfill).

Entry Point — stockNewsNotifier

Instantiates service dependencies at module scope (single composition root) and delegates to the use case. Contains no business logic. FMP_API_KEY is declared with defineSecret('FMP_API_KEY') and bound via secrets: [fmpApiKey].

Operational kill switch: no Remote Config flag — pause/resume the function's Cloud Scheduler job directly in the GCP console. The cursor makes this safe: on resume, the first run detects it is behind the watermark and catches up via deeper pages or the ranged backfill, with no gap and no duplicates.
Overnight window: the schedule deliberately skips 12:00–3:59am EST. The 4:00am run is a routine catch-up: the cursor is ~4h behind, so it fetches deeper pages (or the ranged backfill) and delivers overnight articles as coalesced ~4:00am notifications — no articles are lost, and the per-ticker cooldown prevents a wake-up burst.
  1. Reads process.env.FMP_API_KEY; if missing, logs an error and returns (no retry — misconfiguration is not transient).
  2. Instantiates StockNewsNotifierUseCase with FmpNewsService, FirestoreService, FcmService, and the core FirebaseWatchlistService, then calls execute().
  3. On use-case error: logs and swallows it. The scheduler fires again in ≤ 60 seconds and the cursor guarantees the failed window is re-covered.

Orchestration — Use Case Steps

All steps run sequentially. The only intra-step concurrency is the per-page FMP fetch loop (sequential by design) and per-article writes (Promise.allSettled within one ticker batch). Nothing is fire-and-forget.

  1. Acquire run lease — transaction on stock_news_notifier_state/ingestion: if leaseExpiresAt > now, another invocation is active → log + return. Otherwise set leaseExpiresAt = now + 90s.
  2. Load watched tickers — core FirebaseWatchlistService.getAllWatchedTickers() → Map<ticker, companyName>, cached at module scope for watchlistCacheSeconds (default 300s). Empty map → release lease and return.
  3. Read cursor — lastPublishedDate watermark. First run: bootstrap to now − overlapWindowSeconds in America/New_York, fetch page 0 only.
  4. Fetch since watermark — pages 0..maxPages−1 until oldest item < overlapCutoff; ranged from/to backfill if maxPages exhausted. Fetch failure after retries → release lease, return without advancing the cursor.
  5. Filter + idempotent store — keep publishedDate ≥ overlapCutoff and symbol ∈ watchlist; create() on stock_news/{newsId}; ALREADY_EXISTS → skip silently.
  6. Notify per ticker — group fresh articles by symbol; transactional cooldown claim, then send. 1 article → "{ticker} News" / article title; N → "{ticker}: {N} new stories" / newest title + "... and more" (title truncated so the body stays ≤ 178 chars with the suffix intact).
  7. Advance cursor — transaction: lastPublishedDate = max(current, maxFetchedPublishedDate) — monotonic.
  8. Release lease — best-effort; expiry covers the crash case.
Why claim-before-send: the cooldown claim updates lastNotifiedAt in the same transaction that authorizes the send. A crash after the claim loses at most one notification; it never double-sends. For minute-cadence news a missed push is strictly better than a duplicate.

Failure Isolation

FailureEffect

Data — Domain Types

interface StockNewsArticle {
  symbol: string;          // uppercase ticker, e.g. "AREC"
  publishedDate: string;   // "YYYY-MM-DD HH:mm:ss" — US/Eastern, lexicographically sortable
  publisher: string;
  title: string;
  image: string | null;    // FMP may omit
  site: string;            // source domain, e.g. "proactiveinvestors.com"
  text: string;
  url: string;             // canonical article URL — part of the dedup key
}

interface FetchResult {
  articles: StockNewsArticle[];  // all pages merged, unfiltered
  pagesFetched: number;
  reachedOverlap: boolean;       // false → maxPages hit before overlapCutoff → backfill ran
  maxPublishedDate: string;      // newest publishedDate seen — next cursor value
}

interface IngestionCursor {
  lastPublishedDate: string;     // high-water mark, "YYYY-MM-DD HH:mm:ss"
  leaseExpiresAt: Timestamp;     // run lock; expired lease = no active run
  updatedAt: Timestamp;
}
publishedDate is compared as a plain string everywhere (the FMP format sorts lexicographically). It is parsed as America/New_York only when computing overlapCutoff and the first-run bootstrap watermark — never stored converted.

Service — fmp_news_service.ts

Fetches stock news from the FMP stable API with cursor-aware pagination. Modeled on FmpSecService. Base URL from getRemoteConfig().fmp.baseUrl → https://financialmodelingprep.com/stable; endpoint GET {baseUrl}/news/stock-latest with page, limit, optional from/to, and apikey.

retry(fetchPage, {
  maxAttempts: 3,
  initialDelayMs: 1000,
  backoffFactor: 2,
});   // 1s → 2s → throw

fetchSinceWatermark(watermark, cfg): Promise<FetchResult>

  1. Computes overlapCutoff = watermark − cfg.overlapWindowSeconds.
  2. Fetches pages 0..maxPages−1 (limit pageLimit), stopping early when a page's oldest publishedDate < overlapCutoff or a short page signals feed exhaustion.
  3. If maxPages exhausted without overlap → fetchRange(date(watermark), today, cfg); ranged re-reads whole days, safe because createNewsIfAbsent deduplicates.
  4. Returns { articles, pagesFetched, reachedOverlap, maxPublishedDate }.

fetchRange(from, to, cfg): Promise<StockNewsArticle[]>

Same endpoint with from/to, pages 0..maxBackfillPages−1. Hitting maxBackfillPages logs at ERROR with the boundaries — the alerting signal that a coverage gap may exist.

Mapping: symbol uppercased/trimmed; image normalized to null; items missing symbol, url, or publishedDate dropped with one WARN per run.

Service — firestore_service.ts

Owns every Firestore read/write except the watchlist read (core FirebaseWatchlistService reuse). sha256 doc-ID pattern follows filing_history_service.ts.

FunctionBehaviour
acquireLease()Txn: false if leaseExpiresAt > now; else set now + 90s, return true. Throws on txn failure.
releaseLease()Sets leaseExpiresAt = now (merge). Logged, never thrown.
getCursor()Returns lastPublishedDate or null (first run → caller bootstraps).
advanceCursor(candidate)Txn: lastPublishedDate = max(current, candidate) — monotonic under any interleaving.
createNewsIfAbsent(article)create() with createdAt + expireAt = now + 72h. true = new; false = already-exists (gRPC 6), skipped at DEBUG; other errors logged at ERROR and re-thrown so the cursor advance is withheld.
claimNotificationSlot(ticker, cooldownSeconds)Txn on stock_news_cooldowns/{ticker}: authorize + set lastNotifiedAt atomically. Errors → false (fail closed: prefer a missed notification over a duplicate).

Service — fcm_service.ts

Topic = raw ticker — the same convention realtime_8k_notifier already uses, so clients need no new subscription logic. Feature-local (not core FcmNotificationService) because it needs an APNS collapse id.

{
  topic: ticker,
  notification: { title, body },
  apns: {
    headers: {
      'apns-priority': '10',
      'apns-collapse-id': `news_${ticker}`,   // rapid successive sends replace, not stack
    },
    payload: { aps: { sound: 'default' } },
  },
  android: { collapseKey: `news_${ticker}` },
  data: {
    type: 'stock_news',
    ticker,
    newsId,                   // newest article's doc ID — client deep-link
    url,
    count: String(count),     // FCM data values must be strings
  },
}
Errors are logged and swallowed, never thrown — a failed push must not block cursor advancement or other tickers. No FCM-level retry: the cooldown claim was already consumed, and a delayed duplicate push is worse than a missed one. Sending to a topic with zero subscribers is a silent no-op on FCM's side.

Resolved decisions: FMP publishedDate confirmed US/Eastern — overlap math parses in America/New_York. FMP plan covers the volume; scheduler additionally skips 12:00–3:59am EST (~1,200 runs/day) with overnight articles delivered by the 4:00am catch-up run. Open questions: (1) confirm the front end subscribes to the raw-ticker topic and resubscribes on token rotation; (2) TTL policy must exist per environment before launch.

Infrastructure — Remote Config

New key stock_news_config, created with the JSON data type in the Firebase console (unlike the legacy string-typed fmp_config) so malformed values are rejected at save time. The Admin SDK still returns the value as a string in getTemplate(), so remote-config.ts parses it with JSON.parse exactly like fmp_config, into AppConfig.stock_news. Every tuning knob is runtime-adjustable without a deploy; defaults live in DEFAULT_CONFIG. There is deliberately no enabled flag — pausing the Cloud Scheduler job in the GCP console is the kill switch.

stock_news: {
  pageLimit: number;                    // default 250   — items per FMP page
  maxPages: number;                     // default 4     — latest-feed pages before backfill kicks in
  maxBackfillPages: number;             // default 10    — ranged-fetch safety cap
  overlapWindowSeconds: number;         // default 300   — re-read window behind the cursor
  notificationCooldownSeconds: number;  // default 600   — min gap between pushes per ticker
  watchlistCacheSeconds: number;        // default 300   — per-instance watchlist cache TTL

Design Decisions

Weakness in the original planHardening
"Not already processed" underspecifiedDeterministic doc ID sha256(symbol|url) + create() — the write is the dedup check (one op, race-free)
"No gaps" via ad-hoc page/limit tuningExplicit cursor + overlap window + page-until-overlap + ranged backfill — deterministic guarantee, not heuristics
Overlapping runsmaxInstances: 1 + 90s lease; idempotent writes + monotonic cursor mean even lease failure cannot corrupt state
Notification spam on hot tickersPer-run coalescing + transactional per-ticker cooldown + APNS/Android collapse id
Crash between store and notify → double pushClaim-before-send: worst case one missed push, never a duplicate
Full watchlist read every minutePer-instance cache (default 5 min)
No off switch at ~1,200 runs/dayPause the Cloud Scheduler job in the GCP console (cursor makes resume gap-free); all knobs in Remote Config
Store only watchlisted articles: write volume proportional to user interest; TTL keeps the collection tiny. Backfill-on-subscribe, if wanted later, belongs in a separate on-demand feature.

Setup — Firestore TTL Policy

Must be configured once per environment (dev, qa, prod) before launch — without it, expireAt is inert and the collection grows unbounded.
  1. Select the environment's GCP project: gcloud config set project <project id>
  2. Create the policy: 
    gcloud firestore fields ttls update expireAt \
  --collection-group=stock_news \
  --enable-ttl
  3. Verify with gcloud firestore fields ttls list --collection-group=stock_news — state must show ACTIVE.

Deletion lag: TTL deletes up to 24h after expireAt — treat it as garbage collection. Clients must filter where('expireAt', '>', now). TTL deletes are billed as normal deletes. The client query symbol == X AND expireAt > now will need a composite index in firestore.indexes.json once the front end adds it.
