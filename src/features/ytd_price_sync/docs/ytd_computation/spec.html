YTD Price Sync — YTD Computation
Per-ticker pipeline: one EOD-light fetch · prior-year-close baseline · absolute & % change · idempotent Firestore overwrite

On weekdays, at 10:00 / 12:00 / 14:00 / 17:00 ET, this pipeline reads the global watchlist and keeps one YTD snapshot per ticker in ytd_price_change/{ticker} fresh. For each ticker it makes one FMP EOD-light call spanning mid-December of the prior year through today, derives the YTD baseline (the prior-year final close) and the latest close, computes the absolute and percentage change, and overwrites the document. One API call per ticker per run — the EOD endpoint is single-symbol and no bulk/batch endpoint is on the current FMP plan.

FunctionTriggerSchedule
ytdPriceSyncCloud Scheduler0 10,12,14,17 * * 1-5 (America/New_York) — four discrete fires, no in-code time gate
The keystone property: each run re-fetches the entire year window per ticker and fully overwrites ytd_price_change/{ticker}. Nothing is appended, accumulated, or cursored. Any failure — one ticker, one run, a whole outage — is fully repaired by the next successful fire. Retries, queues, phases, and cohort sharding are structurally unnecessary: the schedule is the retry.

Entry Point — ytdPriceSync

Composition root: getFirebaseAdmin() at module load; stateless singletons (FirestoreService, FirebaseWatchlistService) built at module scope; the key-dependent FmpEodService lazily memoized on first invocation (??=). Delegates to the use case; no business logic. FMP_API_KEY via defineSecret. Unlike stock_price_sync there is no in-code phase gate — the schedule expresses the full policy (four discrete fires), so every invocation runs the complete pipeline.

Orchestration — Use Case Steps

YtdPriceSyncUseCase.execute() owns only the run sequence (resolve dates → load watchlist → per-ticker workflow → summary). The per-ticker body (Step 4) runs concurrently under a fetchConcurrency limit with per-ticker error isolation. The pure derivation lives in snapshot.ts (buildYtdSnapshot) so it is unit-testable without FMP or Firestore.

execute() steps

  1. Resolve dates — today = todayEasternDate(now), year = Number(today.slice(0,4)) (core date_utils).
  2. Load config — cfg = (await getRemoteConfig()).ytd_price_change.
  3. Load watchlist — retry(() => watchlistService.getAllWatchedTickers(cfg.watchlistCacheSeconds), WATCHLIST_RETRY_OPTIONS) (3 attempts, 1s initial, ×2). Exhausted retries → log and return (next fire retries). Empty map → log No tickers watched and return.
  4. Fetch window (computed once) — from = subtractCalendarDays(`${year}-01-01`, cfg.baselineLookbackCalendarDays) (default 15 → mid-Dec prior year, so the prior-year final close is in range across the holiday break); to = today.
  5. Process watchlist — runWithConcurrency(entries, cfg.fetchConcurrency, processTicker) over every [ticker, companyName] (no cohort sharding — the whole list every run). Each processTicker is wrapped so its outcome is tallied and a throw is caught and counted failed — one ticker never aborts the run.
  6. Summary log — written / skipped / failed of N (durationMs); WARN if durationMs > RUN_DURATION_WARN_MS.

processTicker(ctx) → 'written' | 'skipped' | 'failed'

StepActionFailure

There is no in-memory unchanged-skip cache: at four runs/day the write volume is trivial and every run legitimately produces a fresh latestClose, so the skip machinery stock_price_sync needs (~198k intraday writes/day) would earn nothing here.

buildYtdSnapshot(ticker, companyName, year, closes) — pure (snapshot.ts)

Returns YtdChangeSnapshot | null. All date comparisons are lexicographic on "YYYY-MM-DD" strings (no Date parsing).

  1. If closes is empty → return null.
  2. Baseline. baseline = latestCloseBefore(closes, `${year}-01-01`) — the close on the greatest date < Jan 1 (the prior-year final close). If there is no such record (a ticker that first listed this year), or baselineClose === 0 → return null (skipped, no doc written; guards divide-by-zero). Defensive — the watchlist does not carry current-year listings, so in practice every ticker has a prior-year close.
  3. Latest. latest = closeWithMaxDate(closes) — the newest record (≤ today; includes today's row intraday). If none → return null.
  4. ytdChange = latestClose − baselineClose; ytdChangePercent = ytdChange / baselineClose × 100.
  5. Return the fully populated YtdChangeSnapshot (no updatedAt — the Firestore service stamps that).

Domain Types

Defined in models/ — one interface per file, imported from its exact path (e.g. ../models/YtdChangeSnapshot); no barrel index.ts, per the project TypeScript standard.

interface EodClose {
  date: string;   // "YYYY-MM-DD" (ET) — one record per trading day (closed days absent)
  close: number;  // end-of-day close; the FMP EOD-light DTO's `price`
}

interface YtdChangeSnapshot {
  ticker: string;          // uppercase — also the doc ID
  companyName: string;
  year: number;            // Eastern-time calendar year the YTD covers, e.g. 2026
  baselineDate: string;    // "YYYY-MM-DD" of the prior-year final close
  baselineClose: number;   // denominator of the % change
  latestDate: string;      // "YYYY-MM-DD" of the newest close in the series
  latestClose: number;     // the "current" value (includes today's row intraday)
  ytdChange: number;       // latestClose − baselineClose (currency)
  ytdChangePercent: number;// ytdChange / baselineClose × 100
}

interface StoredYtdChange extends YtdChangeSnapshot {
  updatedAt: Timestamp;    // firebase-admin server timestamp at write
}

date strings sort lexicographically (the FMP format sorts correctly); nothing is parsed to Date except the window-date computation, done in America/New_York via core date_utils.

Baseline = prior-year final close. The baseline is always the prior trading year's final close — the newest EodClose with date < `${year}-01-01`. Widening the fetch to mid-December guarantees that record is present for any ticker that traded last year. A ticker with no prior-year record (one that first listed in the current year) yields no baseline, so buildYtdSnapshot returns null and the ticker is skipped — a defensive path, since the watchlist does not carry current-year listings.
Latest / "current". latestClose is the newest record in the same response. The EOD-light endpoint returns today's row during the session (~15-min delayed on the Enterprise plan; verified 2026-07-21), so every one of the four daily runs advances latestClose/latestDate — no separate intraday source is needed.

Firestore Schemas

watchlist/{ticker} — read

Written elsewhere; read via the core FirebaseWatchlistService (getAllWatchedTickers → Map<ticker, companyName>). This feature never writes it: ticker (doc ID), companyName (or name; falls back to the ticker).

ytd_price_change/{ticker} — written

StoredYtdChange — YtdChangeSnapshot plus updatedAt. Full-overwrite set() (never update/merge): the document is a pure projection of the latest fetch, so replacing it wholesale is what makes every run idempotent. One document per ticker, bounded by watchlist size — no TTL, no cleanup function.

Service — fmp_eod_service

Fetches the current year's daily closes for one ticker from the FMP EOD-light endpoint and parses them into EodClose[]. A thin endpoint config over the shared FmpClient — identical endpoint and parsing to stock_price_sync's EOD service, only the window is wider (full year vs a few days).

ItemValue
Base URLgetRemoteConfig().fmp.baseUrl → https://financialmodelingprep.com/stable
EndpointGET {baseUrl}/historical-price-eod/light
Paramssymbol (single ticker), from = Jan 1 − baselineLookbackCalendarDays (mid-Dec prior year), to = today, apikey
nonadjustedomitted → false → split/dividend-adjusted closes (see Open Questions)
ResponseJSON array of daily records { symbol, date, price, volume }, newest first; one record per trading day (closed days absent). Includes today's row during the session (~15-min delayed)

fetchDailyCloses(ticker, window) delegates to client.fetchWindowedRows(FMP_EOD_ENDPOINT, ticker, window) with the EOD descriptor (path, label: 'EOD', error codes, parseRow: parseEodClose). parseEodClose accepts a row only if date is a non-empty string and price is a finite number, mapping to { date, close: price }; invalid rows are dropped and counted in one info log per ticker. Returns the array as returned by FMP; the use case does not assume order — it scans for min/max dates explicitly.

Response handling is delegated entirely to the shared client: non-2xx → AppError('FMP_EOD_FETCH_FAILED', status) (transient statuses retried); non-array body → AppError('FMP_EOD_INVALID_RESPONSE', 422) (permanent); 10s per-attempt timeout. The newest record is the source of latestClose; the newest record before Jan 1 is the baseline.

Service — fmp_client (shared)

The feature's FMP service delegates here. Every FMP call is a single windowed, single-symbol, bounded GET, so the fetch/retry/timeout/validation machinery is factored once and fmp_eod_service.ts becomes a typed endpoint descriptor. Mirrors stock_price_sync/services/fmp_client.ts — the duplication (rather than a shared core/ client) is deliberate (see Design Decisions).

interface FmpEndpoint<T> {
  path: string;                 // '/historical-price-eod/light'
  label: string;                // error/log label ('EOD')
  fetchFailedCode: string;      // AppError code for a non-ok response
  invalidResponseCode: string;  // AppError code for a non-array body
  parseRow: (item: unknown) => T | null;   // boundary validation; null = drop
}

fetchWindowedRows<T>(endpoint, ticker, window): builds {baseUrl}{path}?symbol=…&from=…&to=…&apikey=…, wraps the request in retry() with a 10s AbortSignal.timeout per attempt; non-ok → AppError(fetchFailedCode, status); non-array body → AppError(invalidResponseCode, 422); maps rows via parseRow, dropping nulls with one info log per ticker. Returns the raw (unsorted) validated T[].

Transient policy. Retry maxAttempts 3, 1s → 2s → throw (maxDelayMs 30000). isTransientError retries only AppError.status ∈ {429, 500, 502, 503, 504}, network errors, and timeouts; a 422 non-array body and a malformed-JSON SyntaxError (both FMP contract changes) are not retried — they fail fast and surface. This is the single place the feature's FMP resilience is defined.

Service — firestore_service

upsertYtd(snapshot) — guards a non-empty snapshot.ticker (throws upsertYtd: snapshot.ticker is required before any write), builds a typed YtdWrite (Omit<StoredYtdChange,'updatedAt'> & { updatedAt: FieldValue }), then full-overwrite set() on ytd_price_change/{ticker} with updatedAt: serverTimestamp(). Never merge (stale fields would survive shape changes and break the idempotency argument). Logs Failed to upsert YTD change for {ticker} and rethrows on failure — isolation and counting live in the use case; no in-process retry, the next run's rewrite is the retry. This service does not read Firestore.

Design Decisions

This feature is deliberately a stripped-down stock_price_sync. It reuses that pipeline's keystone property but sheds every piece of machinery that property makes unnecessary at a four-times-a-day cadence.

The keystone property: each run fetches the entire year window per ticker and fully overwrites ytd_price_change/{ticker}. No run depends on any previous run. A failed ticker, a failed run, or a multi-hour outage requires zero recovery — the next successful fire rebuilds every document identically. There is nothing to retry because there is nothing lost. The Pub/Sub-rejection analysis in stock_price_sync applies verbatim and is not repeated.

Baseline = prior-year final close

ytdChange measures the move from the prior trading year's official final close — the newest EOD record with date < `${year}-01-01`. This is the standard financial YTD convention ("since year-end"), not the first-session-of-year open. The single fetch window is widened to mid-December of the prior year (baselineLookbackCalendarDays, default 15) so that record is always present; because EOD records are daily-grained, closed days are simply absent, so "newest record before Jan 1" is always the correct prior-year close with zero holiday-calendar dependency — the market data is the calendar.

Single baseline source — no fallback. The baseline is always the prior-year final close; there is no baselineSource discriminator. The only way a ticker lacks a prior-year record is if it first listed in the current year, and the watchlist does not carry current-year listings — so a would-be fallback branch is unreachable in practice. Rather than carry dead code, buildYtdSnapshot returns null when no prior-year close exists and the ticker is skipped. Rejected: a first_session_of_year fallback with a baselineSource field — it added a field and a code path that would never fire for the tickers this feature processes, and conflated two different meanings ("since year-end" vs "since IPO") in one number. If current-year IPOs are ever added to the watchlist, revisit this deliberately rather than let a silent fallback change what the number means.

"Current" = latest EOD-light record, not a live quote

The EOD-light endpoint includes today's row during the session (~15-min delayed on the Enterprise plan; verified an AAPL call at 12:36 ET on 2026-07-21 returned a same-day row). So a single endpoint supplies both ends of the calculation, and all four daily fires advance latestClose. Rejected: reading the live intraday price stock_price_sync already writes to stock_prices/{ticker} — it would couple the two features and add a second data source for a ~15-minute freshness gain a YTD figure does not need.

No lease, no cohort, no phase gate

DroppedWhy it existed thereWhy it is unnecessary here
Phase gate (phase.ts)One cron couldn't express 9:15 / 9:30 / 4:05 / 4:20 boundaries, so an in-code gate routed each minuteThe schedule is the policy — four discrete fires, each running the identical full pipeline. Cron expresses it directly.
Cohort sharding (cohort.ts, maxCallsPerRun)Per-minute runs could round-robin the watchlist across runs to throttle FMPThis runs 4×/day; sharding across runs would leave tickers stale for hours. The whole watchlist must be processed every fire — one ~500-call burst is well within the 1,500/min quota.
Previous-close warm cache (previous_close.ts)The intraday loop needed previousClose every minute without re-fetchingThe baseline comes from the same single fetch as the latest close; there is nothing to cache across runs.

maxInstances: 1 plus last-write-wins is sufficient — overlapping runs would both write complete valid snapshots, so no transactional lease is warranted.

No unchanged-skip cache

stock_price_sync suppresses writes when the newest 1-min bar is unchanged because it fires ~390×/day. Here the ceiling is watchlist × 4 ≈ 2k writes/day, and every fire legitimately produces a fresh latestClose, so an unchanged-skip cache would add state to save almost nothing. Omitted.

Feature-local FMP client, not a shared core client

The windowed-GET client (services/fmp_client.ts) is copied into this feature rather than promoted to src/core and shared with stock_price_sync. This matches the established convention (each feature owns its services/) and keeps the feature self-contained and independently deployable. The duplication is ~50 lines of stable transport code; extracting a shared client is a cross-feature refactor deferred until a third consumer appears.

Consistency guarantees: Documents — always internally consistent (atomic full overwrite). Freshness — each fire reflects the FMP EOD series at fetch time (~15 min behind intraday); updatedAt/latestDate self-label it. Recovery — unconditional: any failure heals on the next successful fire, no operator action.
